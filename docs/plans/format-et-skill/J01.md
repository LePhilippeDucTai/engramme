# J01 — Analyse des notes : crate `engramme-format`

Context: workspace Cargo racine (`members = ["crates/*"]`, `resolver = "3"`, edition 2024) et bibliothèque `crates/engramme-format` ; API publique `parse_note(path: &Path, source: &str) -> Parsed<Note>` (pure, sans E/S) et `read_note(path: &Path) -> Parsed<Note>` (seule lecture de fichier, dans `fs.rs`) ; le modèle, entièrement `Serialize`, doit servir tel quel à J02 (boîte de réception, base entière, doublons, fixtures sous `tests/fixtures/inbox/` et `tests/fixtures/vault/`), à J03 (la CLI affiche le `Display` de `Diagnostic`) et à J04 (PyO3) ; les briques `source`, `fence`, `frontmatter` et `block` restent `pub(crate)` et réutilisables par J02.
Conventions : lignes numérotées à partir de 1 sur tout le fichier, frontmatter compris ; BOM UTF-8 initial retiré ; découpage par `str::lines()` (LF et CRLF), textes reconstruits avec `\n` ; diagnostics triés par ligne (tri stable) ; messages en anglais, sur une ligne, sans majuscule initiale ni point final (les messages cités entre « » sont exacts, guillemets exclus) ; les lignes `---`, `:::` et `:::<type>` commencent en colonne 0, espaces et tabulations finaux tolérés.
Clôtures de code (sous-ensemble de CommonMark), suivies hors des blocs comme dedans : ouverture = au plus 3 espaces puis au moins 3 accents graves ou 3 tildes (pour les accents graves, aucun accent grave dans le reste de la ligne) ; fermeture = au plus 3 espaces, le même caractère répété au moins autant de fois, puis seulement des blancs ; dans une clôture, `:::`, `:::<type>` et `---` sont du texte.
Dépendances : `serde` (derive), `serde_json` et `serde-saphyr` 2 avec `default-features = false, features = ["deserialize"]` (Rust pur, maintenu ; `serde_yaml`, `serde_norway` et `serde_yaml_ng` n'ont plus de version depuis 2024) ; pas de regex (`strip_prefix` et tests de caractères).
Décisions hors spec : un bloc ne produit une `Card` que s'il n'a aucune erreur (son corps est tout de même validé quand seul l'identifiant est mal formé) ; un bloc réservé ne produit pas de carte (J02 ne le comptera pas parmi les 1 à 3 cartes) ; diagnostics ajoutés au §5 : `invalid-block-header`, `invalid-cloze-deletion` (trou vide, numéro invalide, trou non fermé) et `unreadable-file` (erreurs), `unclosed-code-fence` (avertissement : sans lui, les cartes placées après une clôture jamais fermée disparaîtraient en silence) ; un trou se ferme au premier `}}` de profondeur d'accolades nulle, pour que `{{c1::\frac{a}{b}}}` marche ; les numéros de trous manquants se comptent à partir de 1.
Tests : `crates/engramme-format/tests/notes.rs` (API publique seulement, un test nommé par règle) et fixtures `crates/engramme-format/tests/fixtures/notes/{valid,invalid}/<nom>.md` avec leur instantané `<nom>.json` ; chaque check enchaîne fmt, clippy `-D warnings` et ce test : aucun élément privé inutilisé ne doit rester à la fin d'une tâche.
