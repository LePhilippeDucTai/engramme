# J04 — Paquet Python et CI

Context: J03 fournit `engramme_cli::run(args) -> i32` : `args` commence par le nom du programme (ignoré, ici `sys.argv[0]`), `run` lit `ENGRAMME_DIR`, écrit sur stdout et stderr, vide les deux flux avant de rendre le code (0, 1 ou 2) et n'appelle jamais `process::exit`. Nouveau crate `crates/engramme-py` : bibliothèque `cdylib` nommée `engramme`, en disposition « pur Rust » (maturin génère `engramme/__init__.py`, qui réexporte `main`, à côté de `engramme.abi3.so` ou `.pyd`) ; `#[pyfunction] main` lit `sys.argv` et **rend** le code, et le script console `engramme = "engramme:main"` que pip ou uv génèrent fait `sys.exit(main())` : Python sort normalement (Python n'écrit rien lui-même et vide ses flux en sortant), le lanceur `engramme.exe` de Windows transmet le code ; ni `process::exit` ni `SystemExit` levé à la main.
Versions vérifiées le 2026-10-21 : PyO3 0.30.1 (abandonne Python 3.8, garde `abi3-py39`, MSRV 1.85), maturin 1.15.0. La feature `extension-module` est dépréciée depuis PyO3 0.26 : maturin ≥ 1.9.4 pose lui-même `PYO3_BUILD_EXTENSION_MODULE`, donc ni feature ni `[tool.maturin] features` ; sans elle, PyO3 lie libpython hors maturin, et `[lib] test = false` empêche `cargo test --workspace` de compiler le crate (aucun test Rust : la wheel est testée par `engramme check`), alors que clippy `--all-targets` le vérifie toujours, sans édition de liens. Version `dynamic`, lue dans le workspace (0.1.0) ; licence `MIT` (métadonnées 2.4, `License-Expression`) ; pas de `readme` (le README vient en J05).
Prototype validé sur ce Mac dans un clone jetable, avec exactement les contenus ci-dessous : wheel `engramme-0.1.0-cp39-abi3-macosx_11_0_arm64.whl` ; codes 0 sur `examples/savoir`, 1 sur `crates/engramme-cli/tests/fixtures/broken`, 2 sans chemin ni `ENGRAMME_DIR` ; sortie vidée en tube ; installation par pip sur Python 3.9 ; fmt, clippy, tests, actionlint et l'étape de test du workflow (rejouée sous bash) verts.
CI, un seul workflow `wheels`, donc un seul signal vert : job `checks` (ubuntu, les trois checks globaux) ; job `wheels`, `macos-15` arm64 (`macos-14` est déprécié, actions/runner-images#13518) et `windows-latest` x64, construction native par `PyO3/maturin-action@v1`, puis pip installe la wheel dans un venv Python 3.9 créé par uv (setup-python n'a pas de 3.9 pour macOS arm64 ni pour Windows x64 ; la vérification locale tourne, elle, sur le Python 3.14 d'uvx : les deux bouts de `>=3.9` sont couverts) ; job `release` sur tag `v*` seulement, qui attache les wheels par `softprops/action-gh-release@v3` (la J06 y ajoutera le skill, avec un `actions/checkout`). Aucun tag en J04 : le job `release` sera exercé en J06 par `v0.1.0`.
Windows : le checkout passe les fichiers en CRLF (`core.autocrlf`), ce que l'analyseur gère déjà (`str::lines`, tests `\r\n` de J01–J02) : pas de `.gitattributes` ; les chemins affichés y prennent des `\`, donc le test du workflow ne compare que la ligne de bilan, le code de sortie et `pd.md:12: error:` ; Rust écrit l'UTF-8 tel quel dans un tube (WriteConsoleW en console), et ces sorties sont en ASCII.

`crates/engramme-py/src/lib.rs` :

```rust
//! The `engramme` Python package. Its `engramme` command, a console script
//! declared in `pyproject.toml`, passes `sys.argv` to [`engramme_cli::run`].
#![forbid(unsafe_code)]
#![deny(missing_docs)]

use pyo3::pymodule;

/// The Python module `engramme`.
#[pymodule]
mod engramme {
    use std::ffi::OsString;

    use pyo3::prelude::*;

    /// Runs the command line `sys.argv` and returns its exit code. The console
    /// script passes the code to `sys.exit`, so Python exits normally.
    #[pyfunction]
    fn main(py: Python<'_>) -> PyResult<i32> {
        let argv: Vec<OsString> = py.import("sys")?.getattr("argv")?.extract()?;
        Ok(engramme_cli::run(argv))
    }
}
```

- [ ] T2 — Workflow GitHub Actions `wheels` : créer `.github/workflows/wheels.yml` tel quel (ci-dessous) ; versions majeures des actions vérifiées le 2026-10-21 (checkout v7, setup-python v7, setup-uv v10, upload-artifact v7, download-artifact v8, action-gh-release v3, maturin-action v1, `dtolnay/rust-toolchain@stable`) ; `rust-toolchain: stable` et `dtolnay/rust-toolchain@stable` imposent le dernier rustc stable (le dépôt est développé avec rustc 1.99, l'image d'un runner peut retarder) ; `enable-cache: false` évite l'erreur de fin de job de setup-uv quand il n'y a rien à mettre en cache ; `shell: bash` vaut aussi sous Windows (Git Bash, qui trouve `engramme.exe` sous le nom `engramme`) ; le nom `wheels` est celui que filtrent `gh run list -w wheels` et le check du jalon. Files: `.github/workflows/wheels.yml`. Check: `uvx --from actionlint-py actionlint .github/workflows/wheels.yml`

```yaml
name: wheels

on:
  push:
    branches: [main]
    tags: ["v*"]
  pull_request:
  workflow_dispatch:

permissions:
  contents: read

jobs:
  checks:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy
      - run: cargo fmt --all --check
      - run: cargo clippy --workspace --all-targets -- -D warnings
      - run: cargo test --workspace

  wheels:
    strategy:
      fail-fast: false
      matrix:
        include:
          - os: macos-15
            artifact: wheel-macos-arm64
          - os: windows-latest
            artifact: wheel-windows-x64
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: "3.13"
      - name: Build the wheel
        uses: PyO3/maturin-action@v1
        with:
          command: build
          args: --release --out dist -m crates/engramme-py/Cargo.toml
          rust-toolchain: stable
      - uses: astral-sh/setup-uv@v10
        with:
          enable-cache: false
      - name: Install the wheel with pip on Python 3.9 and run engramme check
        shell: bash
        run: |
          uv venv --python 3.9 --seed .venv-test
          if [ "$RUNNER_OS" = Windows ]; then bin=.venv-test/Scripts; else bin=.venv-test/bin; fi
          "$bin/python" -m pip install --no-index dist/*.whl
          "$bin/engramme" --version
          summary=$("$bin/engramme" check examples/savoir)
          echo "$summary"
          test "$summary" = "checked 6 files: 0 errors, 0 warnings"
          status=0
          "$bin/engramme" check crates/engramme-cli/tests/fixtures/broken > broken.txt || status=$?
          cat broken.txt
          test "$status" -eq 1
          grep -q 'pd.md:12: error:' broken.txt
      - uses: actions/upload-artifact@v7
        with:
          name: ${{ matrix.artifact }}
          path: dist/*.whl
          if-no-files-found: error

  release:
    if: startsWith(github.ref, 'refs/tags/v')
    needs: [checks, wheels]
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/download-artifact@v8
        with:
          pattern: wheel-*
          merge-multiple: true
          path: dist
      - name: Check that the wheels carry the version of the tag
        run: ls dist/engramme-"${GITHUB_REF_NAME#v}"-*.whl
      - uses: softprops/action-gh-release@v3
        with:
          # The capture skill will be attached next to the wheels.
          files: dist/*.whl
          fail_on_unmatched_files: true
          generate_release_notes: true
```
