# engramme — sous-projet 1 : format v1 et skill de capture

Goal: fixer le format v1 de la base (notes Markdown, cartes `qa`/`cloze`, boîte de réception, journal) avec un cœur Rust qui l'analyse et le valide (`engramme check`, distribué en wheel Python), et rendre opérationnelle la capture par les agents, avant que l'app existe. Spec : `docs/superpowers/specs/2026-10-20-format-et-skill-design.md`.
Global checks: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`

## Milestones

- [ ] J01 — Analyse des notes : workspace Cargo, crate `engramme-format`, frontmatter, blocs `qa` et `cloze` (trous `{{cN::…}}`, sous-cartes `id.N`), identifiants, types réservés, diagnostics par fichier et par ligne. Done when: chaque règle des §3.2–3.3 de la spec a un test, et les fixtures Markdown donnent les cartes attendues. Checks: `cargo test -p engramme-format --test notes`
- [ ] J02 — Boîte de réception et validation d'une base : fichiers de `inbox/` (frontmatter obligatoire, `target` sous `notes/`, 1 à 3 cartes sans identifiant), parcours d'une base entière, identifiants en double. Done when: chaque diagnostic du §5 de la spec a au moins un test qui le déclenche. Checks: `cargo test -p engramme-format --test inbox`, `cargo test -p engramme-format --test vault`
- [ ] J03 — CLI `engramme check` et base d'exemple : crate `engramme-cli` (`run(args) -> code`), diagnostics en anglais, `examples/savoir/` valide (notes génériques de risque de crédit, un fichier dans la boîte de réception, `.gitignore`). Done when: la base d'exemple sort en code 0 ; une fixture invalide sort en code 1 avec le bon fichier et la bonne ligne. Checks: `cargo test -p engramme-cli --test check`, `cargo run -q -p engramme-cli -- check examples/savoir`
- [ ] J04 — Paquet Python : crate `engramme-py` (PyO3, maturin, `abi3-py39`), point d'entrée `engramme`, wheel macOS arm64 et wheel Windows `win_amd64` par compilation croisée (cargo-xwin). Done when: la wheel macOS installée dans un environnement isolé valide la base d'exemple, et la wheel Windows est produite. Checks: `rm -rf dist && uvx maturin build --release -m crates/engramme-py/Cargo.toml --out dist && uvx --from dist/engramme-*macosx*.whl engramme check examples/savoir`, `uvx maturin build --release -m crates/engramme-py/Cargo.toml --target x86_64-pc-windows-msvc --out dist && ls dist/engramme-*-win_amd64.whl`
- [ ] J05 — Skill de capture et documentation (en anglais) : `skill/SKILL.md` (`engramme-capture`, règles du §4.1), `skill/INSTALL.md` (installation globale vérifiée pour Claude Code, Codex et Copilot, ligne d'instructions globales, hook `Stop` optionnel), `docs/format.md`, `README.md`, `LICENSE` MIT. Done when: les exemples de `docs/format.md` passent `engramme check`, et le skill est installable en suivant INSTALL.md. Checks: `grep -q '^name: engramme-capture' skill/SKILL.md && test -s skill/INSTALL.md && test -s docs/format.md && test -s README.md && grep -q 'MIT License' LICENSE`
- [ ] J06 — Release et mise en service sur le Mac : release GitHub `v0.1.0` (deux wheels et le skill), CLI installée par `uv tool install` depuis la wheel, skill installé globalement (Claude Code, et Codex si le chemin est confirmé), base perso créée et versionnée avec git, `ENGRAMME_DIR` défini dans `~/.zshenv`. Done when: un agent en session sur le Mac peut écrire une proposition valide dans la base perso. Checks: `gh release view v0.1.0 --json assets -q '.assets[].name' | grep -q win_amd64`, `test -f ~/.claude/skills/engramme-capture/SKILL.md`, `zsh -c '~/.local/bin/engramme check "$ENGRAMME_DIR"'`
